# MathEasy30 Workflow

## Locked Architecture

MathEasy30 uses:

- HTML
- CSS
- JavaScript
- GitHub
- Cloudflare Pages

Do not convert the project to:

- React
- Vite
- Vue
- Angular
- TypeScript
- complex frameworks

---

# Development Rules

1. Full-file replacements whenever possible.
2. Avoid partial patch edits.
3. Preserve stable working versions.
4. Build usable product first.
5. Improve daily after deployment.
6. Mobile-first design.
7. Calm user experience.
8. Avoid clutter and confusing navigation.

---

# AI-Agent Rules

AI agents should:

- update GitHub directly when possible
- preserve architecture
- avoid redesigning the stack
- avoid unnecessary rewrites
- avoid deleting stable systems
- use clear commit messages

---

# Product Direction

MathEasy30 is designed for:

- struggling learners
- special education support
- parents helping children
- confidence-first learning

The product should feel:

- calm
- safe
- encouraging
- simple
- readable
- professional
